# 真实案例：一篇 SCI 论文中译英稿的 before / after

这里不是构造的样稿，是**作者本人一篇桥梁监测论文**（拱桥吊杆索力异常两阶段识别，投稿中）中译英流水线的真实中间产物。

| 文件 | 角色 |
|---|---|
| `zh_source.md` | 中文原稿（已脱敏），7 段正文 |
| `en_draft.md` | 机器**正译初稿**（未经回译比对） |
| `en_refined.md` | **精修稿**（回译比对 + 保真闸 + 人工修正确认后） |
| `term_map.csv` | 全篇术语约定（en-GB 体系） |
| `run_real_case.py` | 一键复现：保真闸 + 增量校验 + 变更分类 |
| `before_after.md` | 由脚本生成的逐段并列对比 |
| `guard_real_report.html` | 由 `report.py` 生成的单文件质检报告 |

## 复现

```bash
cd demo/real-case
python run_real_case.py      # 约 1 秒，全部离线
```

三段输出 + 一份报告：

1. **保真闸**（`guard.py`，中文原稿 vs 精修稿）：10 项检查全 PASS；
2. **增量校验**：初稿 → 精修稿，数字 / 引用 / `Eq.` 编号必须逐字不变；
3. **变更分类**：把词级编辑归入拼写体系、数字形式、术语搭配、标点结构、语义改写五类；
4. 顺带调 `report.py` 生成 `guard_real_report.md` / `.html`（报告内的生成时间会随运行刷新，属正常）。

## 结果

| 指标 | 值 |
|---|---|
| 本条案例块数 | 14（7 段正文 + 7 个标题） |
| 被精修改动的段 | 7 / 14 |
| 编辑点 | 18 |
| 初稿 → 精修的事实级变动 | **0**（数字 51、引用 10、公式编号 1 全部逐字保留） |

编辑点构成：拼写体系归一 6 ／ 术语搭配 1 ／ 标点结构 2 ／ 语义改写 9。
**语义改写集中在摘要一段**（首句立论与末句收口），其余段落只做机械归一——这正是精修应有的形态：
不要为了"看起来改过"而去动本来对的地方。

同一流水线在**全文 359 个单元**上的统计（本节案例是其中 14 块）：

| 指标 | 值 |
|---|---|
| 全文单元 | 359 |
| 精修改动单元 | 42（11.7%） |
| 数字 token | 882 |
| 引用 token | 28 |
| 事实级变动（数字/引用/公式） | **0** |

## 一处诚实披露：闸抓到的那条，是怎么处理的

`en_refined.md` 第 5 段原文写作 `Fifteen zeros are padded at each end`，保真闸在准备本案例时**报出 error**：
中文原稿是数字 `15`，英文写成单词，闸按"数字必须逐字保留"判为丢失。

这条报错的处置不是把 `Fifteen` 直接换成 `15`——**英文句首不宜以阿拉伯数字开头**，
那样修等于用一个文体错误去换一个格式合规。最终改法是让数字离开句首：

```
Fifteen zeros are padded at each end of the convolution ...
→ At each end of the convolution, 15 zeros are padded ...
```

数字回到句中、形式与中文原稿一致，句子读起来也更顺。

值得说清的是：**这条编辑点是闸抓出来的，不是预置的**。闸的价值不在"证明译文没毛病"，
而在把可以机械判定的嫌疑全部摆到桌面上，逼人做一次显式判断；
至于怎么改才既合规又不伤文体，仍然是人的活。

## 这份案例能证明什么，不能证明什么

能证明：

- 精修**没有偷偷改动事实**——882 个数字、28 处引用在 42 个被改单元里零漂移，且可逐块复算；
- 术语与拼写体系（en-US → en-GB）在长稿里能被收敛到单一形态；
- 闸对这种"看起来只是改拼写"的批量操作确实有约束力（它当场抓出了一处数字形式问题）。

不能证明：

- 英文**读起来地不地道**——机械项全对不等于语感好，这一步只能靠人；
- 回译的语义一致性——`en_refined.md` 的回译稿未随案例发布，语义四分类（缺失/添加/扭曲/等价）
  需按 `references/fidelity-rubric.md` 人工判定；
- 源稿本身的技术结论正确——那是审稿人的工作，不是本工具的工作。

## 脱敏规则

| 原文 | 处理 |
|---|---|
| 作者姓名、单位、邮箱、通讯作者信息 | **整段删除**（原稿 G2–G8，不在本案例内） |
| 实桥桥名 | → 某中承式拱桥 / the target arch bridge（中英同步替换，避免数字与引用计数被打乱） |
| 斜拉桥换索案例（C1/C3/C4/C5/C6 通道） | **保留**：原稿本身已用通道代号匿名化 |
| 试验数据、AUC/MAE/准确率等指标 | **保留**：这些是脱敏后仍有价值的部分，也是闸要保护的对象 |

技术内容按作者意愿保留，仅移除可识别作者身份的信息。
