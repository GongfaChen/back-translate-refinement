# 质检报告字段说明（Report Spec）

`report.py` 生成的报告（Markdown + 单文件 HTML）供直接转发。本文说明每个部分怎么读、哪些数字该看、哪些结论不能由报告给出。

## 报告结构

| 章节 | 内容 | 转发时怎么用 |
|---|---|---|
| 结论横幅 | PASS / WARN / FAIL + 硬错误/复核/检查项计数 | 一眼看交付状态：FAIL = 不可交付 |
| 一、关键指标 | 段数、字数、长度比、受保护元素数 | 与原稿规模对照，确认没有大块漏译 |
| 二、检查项一览 | 10 项检查 × 通过状态 | 逐项核对，关注「未过」行 |
| 三、必须修正 | error 明细，定位到段号 | 逐条修完再交付 |
| 四、建议复核 | warn 明细 | 人工判断，不是必改 |
| 五、逐段状态 | 每段状态/字数/比值/问题 | 快速定位哪几段要重点读 |
| 六、可复现信息 | 输入文件 sha256 + 完整命令 | 同一输入重跑必然得到同一结论 |
| 七、报告的边界 | 明确「不覆盖语义」 | 转发时防止对方误当成语义验收 |

## 关键数字的解读

**整体长度比（英文词/汉字）**：技术文本合理带约 0.35–1.10。

- 低于 0.35：大面积漏译的强信号
- 高于 1.10：扩写/解释性翻译（常见于把中文省略的主语补全）
- 单段比值异常但整体正常 → 只看那一段

**回译相对原稿汉字比**：0.65–1.45 为合理带。

- 偏短：语义在往返中被压缩（英文太简略）
- 偏长：英文添加了原文没有的解释

**受保护元素计数**：占位符/公式/引用/数字的数量是「应保留清单」的规模。译稿侧的对应多重集必须完全相等——不等就是 error。

## 结论语义（严格定义）

| 结论 | 定义 | 交付建议 |
|---|---|---|
| PASS | 无 error、无 warn | 机械层干净；语义比对（SKILL.md Step 5）仍需做 |
| WARN | 无 error，有 warn | warn 逐条人工判断后可交付 |
| FAIL | 有 error | **不可交付**；修完重跑 |

## 报告不能做的事（转前必读）

1. **不能证明语义一致**。报告 PASS 只说明：段都在、公式都在、数字没变、术语用了规定译法。「意思没走样」只有语义比对能回答。
2. **长度比是启发式**。越界 ≠ 错误：表格密集的段落比值天然偏低；图注式短段会被跳过。
3. **术语检查是单向的**。只查「原文含术语 → 译稿须含规定译法」；译稿合法省略术语（代词化）不会误报，但也查不出「译稿新增了原文没有的术语」——那是语义添加，归 Step 5。
4. **docx 的公式校验是对象级**（数 `<m:oMath>` 数量），不做公式内容逐字比对；内容级校验需把公式导出为 LaTeX 后再跑 guard。
