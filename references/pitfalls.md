# 实战坑清单（Pitfalls）

来自真实回译精修的坑，按 6 类整理。每条：**现象 → 根因 → 防法**。
「防法」标注了由哪一层拦：`[guard]`（脚本自动拦）/ `[流程]`（SKILL.md 步骤约束）/ `[人工]`（只能靠人）。

---

## 一、占位符与结构化元素

1. **公式在正译时被「顺手翻译」成英文描述**（`$O(n^2)$` → O of n squared）
   根因：模型把行内公式当普通文本处理。
   防法 `[流程]`：Step 2 前先跑 probe，公式清单在手；Step 2 逐处加 `<KEEP:math:N>`。

2. **占位符 ID 在修正轮中重排**
   根因：重译某段时模型重新编号，导致第 3 段的图和第 5 段的图互换。
   防法 `[guard]`：keep 多重集 + 顺序单调两道检查，互换会被抓。

3. **表格被逐格翻译，段号炸掉**
   根因：整表在 Markdown 里是多行块，译者按行翻译并保留表格语法，回译侧段数对不上。
   防法 `[流程]`：整表一个 `<KEEP:table:N>` 占位；表内文字如需翻译另建对照，不占正文段号。

4. **图片 caption 被单独译出，元素本体却丢了**
   根因：caption 是「看起来该翻译的文字」，本体块被当成无关内容跳过。
   防法 `[guard]`：keep 数量校验；`[流程]`：规范规定 caption 与本体同 ID 占位。

5. **引用格式被「规范化」**：`[1]` → `(1)`，`[2-3]` → `[2,3]`
   根因：模型按英文期刊惯例改写。
   防法 `[guard]`：cite 多重集逐字比较。

6. **文末参考文献被翻译**
   根因：参考文献列表看起来是「正文」。
   防法 `[流程]`：整节一个占位符。

7. **docx 公式转纯文本时整段消失**
   根因：OMML 公式不在文本层，`python-docx` 取段落文本拿不到。
   防法 `[guard/probe]`：probe 检测「docx 有公式对象但文本无公式」，标「高」级风险；处理 docx 保留原文件，文本侧逐处占位。

8. **作者-年份引用被回译改写**：(Zhang et al., 2023) → (Zhang et al, 2023年)
   根因：回译模型把年份本地化。
   防法 `[流程]`：作者-年份制引用建议也占位（structured-preservation.md）。

## 二、数字与单位

9. **数字被改成「合理」的数字**：12M 参数 → 21M
   根因：模型幻觉或笔误；这是最容易被下游审稿抓到、也最难靠肉眼复查的错。
   防法 `[guard]`：数字多重集逐段比较——本工具最核心的存在理由之一。

10. **全角/半角数字混用导致假报**
    根因：中文稿写 `５０％`，英文写 `50%`。
    防法 `[guard]`：抽取层全角统一转半角后再比。

11. **公式里的数字被重复计数**：`$O(n^2)$` 里的 2
    根因：先抽数字再抽公式，顺序错了。
    防法 `[guard]`：抽取顺序固定为 KEEP → 行间公式 → 行内公式 → 引用 → 数字（bt_common 固化）。

12. **单位换算**：12M → 12 million
    根因：译者觉得英文该写全。
    防法 `[流程]`：术语表加「单位与数量词不换写」规则；单位写进 glossary 用规定形式。

13. **小数点精度漂移**：0.0001 → 0.00010 / 1e-4
    防法 `[guard]`：逐字比较会抓住（0.00010 归一后仍不同）；1e-4 抓不住，`[人工]` 对科学计数法敏感段重点复核。

## 三、术语与一致性

14. **同一概念两种译法**：attention mechanism / focus mechanism 混用
    根因：无术语表，逐段翻译时模型即兴发挥。
    防法 `[guard]`：术语一致性检查；`[流程]`：Step 1 先固化术语表。

15. **术语表本身有冲突**（同 zh 两译法 / 同 en 对应多 zh）
    防法 `[guard]`：`glossary.py validate`。

16. **缩写首次出现后开始裸用**：首次 self-attention (SA)，后文直接 SA
    防法 `[人工]`：术语表记全称与缩写的映射；guard 查全称所在段。

17. **中文惯用语直译后歧义**：「鲁棒性」→ robustness ✓，「强度」→ strength/intensity 语境而定
    防法 `[人工]`：多义术语在 glossary note 列写清语境。

## 四、分段与对齐

18. **段数对不上就硬比**
    根因：译者合并/拆分段落。
    防法 `[guard]`：coverage 是第一项检查，段数不一致直接 FAIL 并提示「先对齐段号再谈保真」。

19. **Markdown 标题行被当成正文翻译**，导致块错位
    防法 `[流程]`：标题也按段占位（可译，但占一个段号）；或整篇先转成纯段落流。

20. **列表项被合并成一个段落**
    根因：中文列表 `-` 项在英文侧被写成整段。
    防法 `[guard]`：coverage + 相邻重复/长度检查会暴露异常段落；`[流程]`：列表项保持逐项对应。

21. **分批处理时 ID 按批重编**
    根因：第 2 批从 `<KEEP:figure:1>` 重新开始。
    防法 `[流程]`：ID 全篇递增；`[guard]`：合并后跑全篇 guard，重复 ID 直接爆。

## 五、回译机制本身

22. **回译偷看原稿**
    根因：模型有对话上下文，把原稿「记住了」，回译时自动补上损耗，比对永远 PASS。
    防法 `[流程]`：回译必须盲（新会话/不提供原稿）。这是整个机制的根基，值得为它单开会话。

23. **把回译稿当成了修订目标**
    根因：回译稿读起来更通顺，忍不住照它改原稿。
    防法 `[流程]`：基准永远是中文原稿；回译稿只提供差异信号。

24. **迭代震荡**：改 A 又错 B，来回抖
    根因：英文句式表达能力上限。
    防法 `[流程]`：连续 2 轮无改进即停（SKILL.md Step 4 约束），二选一交给用户。

25. **修语义时顺手破坏结构**
    根因：改句子时删了半个公式/一个占位符。
    防法 `[guard]`：每修一轮重跑 guard。

26. **无信息量补全被误判为语义添加**
    根因：英文语法需要主语/冠词。
    防法 `[人工]`：rubric 明确「语法需要 ≠ 语义存在」。

## 六、文档格式

27. **LaTeX 环境被翻译器拆坏**：`\begin{align}...\end{align}` 中间被断行改写
    防法 `[流程]`：整环境一个 `<KEEP:eq:N>`。

28. **中文标点残留英文稿**：，。；出现在英文段落里
    根因：复制粘贴或局部未改。
    防法 `[guard]`：residue 检查抓汉字；标点可看逐段文本。

29. **Markdown 加粗/链接语法被丢**
    根因：翻译时只保留文字。
    防法 `[人工]`：交付前 diff 语法标记；后续版本可加「Markdown 语法标记多重集」检查。

30. **行尾反斜杠/续行符丢失**（LaTeX 多行公式）
    防法 `[guard]`：公式逐字比较覆盖；`[人工]`：非公式区域的续行符检查未自动化，交付前全文搜 `\`。

---

## 坑的使用方式

- **每次开工前**：probe 报告会映射到这里相关的坑（公式多 → 1/7/11/13/27；段数多 → 18/21/22）。
- **收到 guard 报告后**：按坑号查根因，别直接改——根因不改，下一轮还会爆。
- **发现新坑**：补进本文件（提交时注明来源文档），这是这个仓库最重要的复利资产。
