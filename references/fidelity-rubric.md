# 语义保真判定标准（Fidelity Rubric）

Step 5 语义比对与修正的判定标准。与 `guard.py` 的分工：**guard 判机械项（结构/数字/公式），本文件管语义**。两层都过，才算交付。

## 唯一基准

**用户的中文原稿是语义基准**。回译稿只是检测探针，它自己翻得不好不算问题——它「如实暴露了英文稿的语义」才是功能所在。

## 四类差异及判定

### 1. 语义缺失（omission）

原稿表达的含义在回译稿中**找不到**。

- 判定：原稿中一个独立的信息单元（主张、条件、限定、结论、让步）在回译稿中无对应表述。
- 典型形态：定语从句被吞、限定条件（"仅在……时"）消失、并列项少了一项、让步关系（"虽然……但是"）丢了前半。
- 常见根因：英文句子过长被截断；译者合并句子时漏了分支。
- 修法：补回英文；若因英文过长导致，拆成两句再补。

### 2. 语义添加（addition）

回译稿中出现原稿**没有**的含义。

- 判定：回译稿中的信息单元在原稿中无出处。
- 典型形态：补出的因果解释、加上的限定词（"通常""一般"）、多出来的总结句。
- 特别注意：翻译腔的「补全」最常见——英文语法需要主语，译者补了"研究表明"之类。**语法需要 ≠ 语义存在**，无信息量的补全可接受，有信息量的必须删。

### 3. 语义扭曲（distortion）

核心含义被改变、弱化或反转。

- 判定：回译稿说的「是另一件事」或「程度不同」。
- 典型形态：
  - 程度词漂移：显著 → 相对明显；必须 → 最好
  - 否定范围变化：不是 A 而是 B → 不是 A 和 B
  - 因果方向反转：A 导致 B → B 导致 A
  - 范围扩大/缩小：本方法 → 该类方法
- 修法优先级：调整英文的限定词与句式 > 重写整句。

### 4. 术语不一致（terminology）

同一概念前后译法不统一，或偏离术语表。

- 判定：概念 C 在原稿中始终叫 T₁，译稿中出现 T₁ 与 T₂ 两种译法；或术语表规定译法 E，译稿用了 E′。
- 术语表未收录的术语：先补进术语表再修译文（修完后重新 validate）。
- 注意与「机械项」的分工：术语表**已有**译法但译稿没用到，guard 会报 warn；这里处理的是 guard 覆盖不到的上下文变体。

## 「实质含义一致」的判定

允许（不算差异）：

- 措辞、语序、句式不同（被动/主动、长短句拆合）
- 语法必需的功能词（冠词、形式主语）
- 无信息量的衔接词（moreover / 此外）
- 英文惯例的省略（避免重复主语而用代词）

不允许（算差异）：

- 任何信息单元的增删改（上面的四类）
- 逻辑关系改变（因果/让步/并列/转折互相替换）
- 数量与程度词的任何变化（这个由 guard 的数字保真兜底，但程度词只能语义层判）

## 迭代控制

- 上限默认 **5 轮**；达到上限仍有差异 → 记入修改记录、向用户列出，不再循环。
- **同一段连续 2 轮无改进即停**——说明差异根因在英文句式的表达能力上限，继续微调只会震荡。此时给出两个选项供用户选：(a) 接受当前近似；(b) 改写原句中文表达后重翻（需用户确认，因为这动了原稿）。
- 每轮修正只动有差异的段落；已一致段落禁止「顺手优化」。

## 与 guard 的协作顺序

1. Step 4 硬闸先跑：error 不清零禁止进入语义比对（在数字都被改错的稿子上谈语义是浪费时间）；
2. 语义比对每修一轮，**重跑一次 guard**（修语义时很容易顺手破坏结构，比如删掉半个公式）；
3. 终态 = guard PASS/WARN **且** 语义比对无未决差异。
